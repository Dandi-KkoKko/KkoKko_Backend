## T-001. Post 상태 컬럼이 MySQL enum으로 생성됨

- 날짜: 2026-10-29 · 영역: DB · 상태: 해결 (`7c7c443`)

**문제**: `@Enumerated(EnumType.STRING)`을 붙인 `Post.status`가 MySQL에서 `varchar`가 아니라 네이티브 `enum('VISIBLE','HIDDEN','DELETED')` 컬럼으로 만들어졌다.

**왜 문제인가**: 나중에 상태 값을 추가하면 `ddl-auto=update`는 이미 있는 컬럼의 타입을 고치지 않는다. 새 값을 저장하는 순간 DB 오류가 난다.

**해결**: `@JdbcTypeCode(SqlTypes.VARCHAR)`를 붙여 `varchar(20)`으로 만들게 했다. 이유를 엔티티 주석과 [ERD 설계 이유](ERD.md#설계-이유)에 남겼다.

**배운 점**: 엔티티를 만든 뒤 실제 DB에 생긴 컬럼 타입(`SHOW CREATE TABLE`)까지 확인한다.

## T-002. Zone 반경 컬럼 이름이 `radiusm`으로 생성됨

- 날짜: 2026-10-29 · 영역: DB · 상태: 해결 (`0933b8e`)

**문제**: 필드 `radiusM`이 ERD의 `radius_m`이 아니라 `radiusm` 컬럼으로 만들어졌다.

**원인**: Spring의 기본 네이밍 규칙은 소문자 뒤에 대문자가 오고 그 뒤에 소문자가 이어질 때 밑줄을 넣는다. 끝에 대문자 한 글자만 있으면 밑줄 없이 소문자로 바꾼다.

**해결**: `@Column(name = "radius_m")`로 이름을 직접 지정했다.

**배운 점**: `xxxM`, `xxxId` 같은 짧은 접미사 필드는 컬럼 이름을 확인한다. data.sql을 손으로 쓸 때 컬럼 이름이 다르면 바로 실패한다.

## T-003. 격자 스냅 이웃 간격 테스트가 20.97m로 실패

- 날짜: 2026-10-29 · 영역: 위치 유틸 · 상태: 해결 (`d26cd45`, 테스트 수정)

**문제**: "이웃한 격자점 사이 거리는 20m"라는 테스트에서 위아래 행 사이 거리가 20m가 아니라 20.97m로 나왔다.

**원인**: `GeoUtils.snap`은 행(위도)마다 경도 간격을 `latStep / cos(그 행의 위도)`로 다시 계산한다. 그래야 어느 위도에서도 가로 간격이 20m가 된다. 대신 행마다 열의 위치가 조금씩 달라서, 바로 위 행의 격자점이 정확히 수직 위에 있지 않다(약 6m 어긋남). 테스트가 "위 행의 같은 열"을 이웃으로 잡아 대각선 거리를 잰 것이다.

**해결**: 구현은 유지하고 테스트를 고쳤다. 같은 행 안의 가로 간격과 행 사이 세로 간격을 따로 재서 각각 20m(오차 0.01m)인지 확인한다.

**배운 점**: 테스트가 깨졌을 때 기대값부터 바꾸지 않고 원인을 먼저 찾는다. 이번엔 구현이 맞고 테스트의 "이웃" 정의가 틀렸다. 이 성질은 PR #6 리뷰어에게도 알렸다.

## T-004. EC2를 서울이 아닌 시드니 리전에 생성

- 날짜: 2026-10-29 · 영역: 인프라 · 상태: 조치 중

**문제**: 개발 서버 EC2를 만든 뒤 SSH로 인스턴스 메타데이터(IMDSv2)를 확인하니 리전이 `ap-southeast-2`(시드니)였다. 팀 기준은 `ap-northeast-2`(서울)다.

**왜 문제인가**: 한국 사용자와 거리가 멀어 응답이 느리다. S3 버킷(서울)과 리전이 달라 리전 간 전송이 생긴다. EC2는 다른 리전으로 옮길 수 없다.

**조치**: 서울 리전에서 키 페어, 보안 그룹, 인스턴스, 탄력적 IP를 새로 만든다. 시드니 쪽 리소스(인스턴스, 탄력적 IP)는 정리한다. 탄력적 IP는 보유하는 동안 과금된다.

**배운 점**: 리소스를 만들기 전에 콘솔 오른쪽 위 리전을 확인한다. 만든 뒤에는 메타데이터로 리전을 다시 확인한다.

## T-005. 보안 그룹 규칙 중복 오류

- 날짜: 2026-10-29 · 영역: 인프라 · 상태: 해결

**문제**: 인스턴스 생성 화면에서 보안 그룹 규칙을 추가하자 "프로토콜, 포트 범위 및 소스가 동일한 보안 그룹 규칙이 이미 이 보안 그룹에 추가되었습니다"라는 오류가 났다.

**원인 (추정)**: 생성 화면의 "인터넷에서 HTTP 트래픽 허용" 체크박스로 이미 80번 규칙이 들어간 상태에서, 같은 규칙을 편집 화면에서 한 번 더 추가했다.

**해결**: 중복 규칙을 지웠다. 최종 규칙은 SSH 22(내 IP), HTTP 80 두 개다 ([ADR 0003 보안 그룹](adr/0003-deploy-ec2-docker-ghcr.md#보안-그룹)).

**배운 점**: 체크박스로 만든 규칙과 직접 추가한 규칙이 겹치는지 편집 전에 본다.

### W-001. 지도에 사진을 불러오는 방식

- 날짜: 2026-10-29 회의에서 제기 · 영역: 지도(`MapService`) · 담당: BE-B

**현재 계획** ([ARCHITECTURE](ARCHITECTURE.md), PRD 기준)
- `GET /api/v1/map/zones?lat&lng&radius`가 반경 안의 구역(zone)마다 사진 개수와 대표 사진(일반 1장, 랜드마크 최대 2장)을 내려준다.
- 대표 사진은 거리 단계에 맞는 이미지 URL 하나만 준다. 사진이 0개인 구역도 빈 구역으로 내려준다.

**지켜볼 점**: 회의에서 이 방식으로 만들고 테스트할 때 문제가 생길 수 있다고 이야기했다. 어떤 부분이 걱정인지는 구체적으로 정리해 이 항목에 추가한다.

**처리**: 구현하고 테스트해서 문제가 없으면 이 항목을 닫는다. 방식을 바꿔야 하면 T 항목으로 옮겨 문제, 원인, 바꾼 방식을 기록하고, 필요하면 ADR을 쓴다.
