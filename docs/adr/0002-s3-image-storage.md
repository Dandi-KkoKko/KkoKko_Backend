# ADR 0002. 사진은 S3 비공개 버킷 + presigned URL로 내려준다

- 날짜: 2026-10-29
- 상태: 채택 (구현 전)

## 배경

- 사진 한 장마다 흐림 단계별 이미지 5개를 둔다: `{image_key}/s0.jpg`, `s1`, `s2`, `open`, `original` ([ERD](../ERD.md#post)).
- 서비스의 핵심 규칙은 "가까이 가야 열린다"다. 그래서 **멀리 있는 사용자가 선명한 이미지(`open`, `original`) 주소를 알아내도 받을 수 없어야 한다.**
- 서버는 EC2 한 대(t3.small, 디스크 약 30GB)에서 Spring과 MySQL을 같이 돌린다 ([ADR 0003](0003-deploy-ec2-docker-ghcr.md)).

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| EC2 디스크에 저장하고 Spring이 직접 내려준다 | 추가 서비스가 없다 | 인스턴스를 다시 만들면 사진이 같이 사라진다. 이미지 전송이 API 서버 메모리·대역폭을 같이 쓴다. 디스크가 차면 DB도 같이 멈춘다 |
| S3 공개 버킷 | 구현이 가장 쉽다 | 주소만 알면 누구나 선명한 이미지를 받는다. 핵심 규칙이 깨진다 |
| **S3 비공개 버킷 + presigned URL** | 서버가 단계를 판정한 뒤 그 단계 파일의 주소만, 짧은 시간 동안 유효하게 내준다. 사진이 서버와 분리돼 서버를 다시 만들어도 남는다 | 버킷·IAM 설정이 필요하다. URL이 만료되면 앱이 다시 받아야 한다 |

## 결정

**S3 비공개 버킷 + presigned URL**을 쓴다.

- 리전은 EC2와 같은 시드니(`ap-southeast-2`). 계정 리전이 고정되어 있고([T-004](../TROUBLESHOOTING.md#t-004-ec2를-서울이-아닌-시드니-리전에-생성)), 같은 리전이어야 전송 비용이 없다. 버킷의 퍼블릭 액세스 차단은 모두 켠다.
- 서버는 응답을 만들 때 `BlurStage`(거리 단계)로 고른 파일 하나에 대해서만 presigned GET URL을 발급한다.
  - 예: 150m 밖이면 `s0.jpg` 주소만 나가고, `open`·`original` 주소는 응답에 아예 없다.
  - `original`은 클라이언트에 내려주지 않는다(재가공용 보관).
- URL 만료 시간은 짧게(분 단위) 두고, 목록·열기 응답마다 새로 발급한다. 정확한 값은 `application.properties`로 뺀다.
- EC2에서 S3에 접근할 때는 **EC2 IAM 역할**을 쓴다. 액세스 키를 `.env`나 코드에 두지 않는다.
  - AWS SDK for Java v2는 기본 자격 증명 체인의 마지막 단계에서 인스턴스 프로필의 임시 자격 증명을 읽고 주기적으로 갱신한다(SDK 개발자 가이드 "IAM roles for EC2").
  - 역할 권한은 이 버킷의 `s3:GetObject`, `s3:PutObject`로만 좁힌다.
- 로컬 개발에서 S3를 어떻게 쓸지(개인 자격 증명, 로컬 대체 저장소 등)는 `ImageService` 구현 때 정한다.

## 결과

- `ImageService.urlFor(post, stage)`(BE-A)가 presigned URL을 만들고, 지도·목록·열기 응답(BE-B)은 이 메서드만 부른다.
- 업로드 시 단계별 이미지 5개를 만들어 S3에 올리는 것은 BE-A 업로드 기능에 포함된다.
- 사진 파일은 EC2를 지우거나 다시 만들어도 남는다. 대회가 끝나면 버킷 정리가 필요하다.

## 정할 것

- [ ] 버킷 이름과 만드는 사람(계정은 승윤 AWS 계정). EC2 IAM 역할은 BE-B, 버킷 사용 코드(`S3Config`, `ImageService`)는 BE-A.
- [ ] presigned URL 만료 시간 값
