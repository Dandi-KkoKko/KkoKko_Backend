# ADR (기술 결정 기록)

선택지가 여럿이고 나중에 "왜 이렇게 했지?"라는 질문이 나올 만한 결정을 하나씩 남깁니다.

## 목록

| 번호 | 제목 | 상태 |
|---|---|---|
| [0001](0001-spring-boot-3.5.md) | Spring Boot 3.5.16 + Java 17 + Gradle 8.14 | 채택 |
| [0002](0002-s3-image-storage.md) | 사진은 S3 비공개 버킷 + presigned URL로 내려준다 | 채택 (구현 전) |
| [0003](0003-deploy-ec2-docker-ghcr.md) | EC2 + Docker Compose + GitHub Actions(GHCR)로 자동 배포한다 | 채택 (구현 중) |

## 언제 쓰나

- 라이브러리·인프라·저장 방식처럼 되돌리기 비싼 결정
- 두 사람의 담당 영역에 함께 걸치는 결정
- PRD와 다르게 가기로 한 결정

**구현 전에 먼저 씁니다.** 상태를 `제안`으로 PR을 올리고, 상대가 승인하면 `채택`으로 바꾼 뒤 구현을 시작합니다. 결정이 바뀌면 기존 문서를 지우지 않고 상태를 `대체됨 (→ 000N)`으로 바꾸고 새 ADR을 씁니다.

## 파일 이름

`000N-짧은-영문-제목.md` (번호는 4자리, 순서대로)

## 템플릿

```markdown
# ADR 000N. 결정을 한 문장으로

- 날짜: YYYY-MM-DD
- 상태: 제안 | 채택 | 채택 (구현 중) | 대체됨 (→ 000M)

## 배경
왜 이 결정이 필요한가. 제약 조건(일정, 비용, 인원, 규칙).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|

## 결정
무엇을 고르고, 구체적으로 어떻게 쓰는가.

## 결과
이 결정으로 생기는 일, 감수하는 단점, 후속 작업.

## 정할 것
- [ ] 아직 열려 있는 항목
```
